## Week 1

### VPC

A Virtual Private Server gives you a private , isolated network boundary. Your own address space. Your own routing rules, your own firewall. so your infrastructure behaves like it's sitting in a private data center, even though it's running on AWS's shared hardware.

### Avaliability Zone

An avaliability zone consists of one or more data centers with redundant powerr network and connectivity.

### Region

Group of Avaliability Zones

### AWS IAM

Authentication is verifying if someone who they say they are. Authorization is do you have the correct permissions.

### ECS (Elastic Container Service)

AWS-native way to run Docker containers. You define a **task** (your container + CPU/memory), group tasks into a **service** (keeps desired count running), and put everything in a **cluster**.

Two launch types:
- **Fargate** — AWS runs the servers. You only manage containers. Less ops, slightly higher cost.
- **EC2** — You manage the EC2 instances. More control, more work.

Best when: you want containers on AWS without Kubernetes complexity.

Key terms: Task Definition, Service, Cluster, Fargate, EC2 launch type.

### EKS (Elastic Kubernetes Service)

Managed **Kubernetes** on AWS. AWS runs the control plane; you run worker nodes (EC2 or Fargate).

Same K8s tools everywhere: `kubectl`, Helm, Deployments, Services, Ingress.

Best when: you already use Kubernetes, need portability, or want the full K8s ecosystem.

**ECS vs EKS (quick pick):**
- ECS → simpler, AWS-only, faster to start
- EKS → standard K8s, portable, more flexible, more ops

### Serverless

You write code; AWS runs and scales it. No servers to patch or size.

**Lambda** — run functions on events (API call, S3 upload, queue message). Pay per invocation + duration. Max 15 min runtime. Watch for **cold starts**.

**API Gateway** — front door for HTTP APIs that trigger Lambda (or other backends).

**EventBridge** — event bus. Services publish events; rules route them to targets.

**Step Functions** — orchestrate multi-step workflows (retries, branching, timeouts).

**SQS / SNS** — async messaging. Decouple producers from consumers.

Serverless fits: spiky traffic, event-driven work, small focused tasks. Less fit: long-running jobs, steady heavy compute, low-latency sensitive apps with cold-start risk.
